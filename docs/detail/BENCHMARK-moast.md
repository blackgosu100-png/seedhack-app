# 벤치마킹 — Moast(moast.ai) 상세페이지 생성 흐름 (사용자 HAR·화면 캡처, 2026-10-09)

대상 상품: 1688 offer 841080065939 (화이트 커피머신 수납 슬라이드 서랍 선반). 사용자가 직접 실행한 세션의 HAR(요청 구조·응답 형태만 분석, 인증 정보 미사용).

## 흐름 (화면 순서)
1. 링크 입력 → **URL 상품 정보 수집 → 수집 데이터 AI 분석 → 상세페이지 기획 → 디자인 시스템 세팅 → 최종 데이터 분석·세팅** (진행 단계 5개 표시)
2. "상품 정보를 가져왔어요" 확인 화면(사람이 고치는 단계) — 여기까지가 1단계
   - ① 상품 이미지(대표) 5장: "AI 이미지 선별 — 불필요한 사진은 AI가 제외"
   - ② 상세 이미지 15장 + **이미지에서 추출한 텍스트(이미지별)** 펼쳐 보기, 용량 초과분 자동 제외
   - ③ 상품명(한글, 판매용으로 다듬은 이름)
   - ④ 상품정보 = **기획서(keyContent)** 텍스트 — "AI 정보추출" 버튼, 직접 수정 가능
   - ⑤ 디자인 스타일: 템플릿 갤러리에서 **AI 추천** + "나만의 레퍼런스 만들기" + **AI가 분석한 디자인 톤앤매너**(배경·베이스·포인트 색, 톤, 조명 문장)
   - "9개 섹션 · 90 크레딧" → 상세페이지 생성하기 (2단계)
3. 2단계: 섹션별로 이미지 생성(템플릿 미리보기 PNG를 레퍼런스로 섹션 단위 생성으로 보임)

## 수집 API 응답 구조 (POST ml.moast.ai/scrapper, 약 55초, 한 번은 100초 후 실패)
- `crawlerType: "1688"`, `sourceDomain: "m.1688.com"` — **모바일 페이지**로 수집
- `productName`(판매용 한글명), `titleText`(원제목 번역), `offerId`, `templateId`(추천 템플릿)
- `productImages[5]`(대표 사진, 선별 후), `detailImages[15]{ imageUrl, text }` — **이미지마다 OCR+번역 한글 텍스트**
- `keyContent` — 아래 7단 기획서(한글):
  상품 유형 / 핵심 소구 / 주요 장점(불릿) / 상세 구성·스펙 / 추천 타겟 / **상세페이지 기획 방향**(첫 화면→초반→중반→디테일→후반→마지막) / **주의할 표현**(확인 안 된 수치·인증·단정 표현, 이미지 속 소품은 구성품 아닐 수 있음 등)
- `color` — **제품별 디자인 시스템**: colorPalette[5], accentColors[4], backgroundColor, backgroundTone(문장), lighting(문장), materialMood(문장), typographyTone(문장), **sectionConsistencyRules[10]**(모든 섹션 공통 규칙), **forbiddenProductUsageNote**(제품 사진이 없는 섹션에 제품을 새로 그려 넣지 말 것)

# 2단계 — 상세페이지 생성 (HAR2, 같은 상품 841080065939)

## Moast가 실제로 하는 일
- `POST ml.moast.ai/page/url` 한 번(**약 6.6분**): 입력 = keyContent(기획서) + productName + productImages[5] + detailImages[15]{imageUrl,text} + color(디자인 시스템) + **templateId + sections[9]{sectionId, seq}**.
- 결과는 섹션 9개가 **각각 한 장의 완성 이미지**(1344×2016 PNG, 한글 글자까지 그림 안에 생성). 섹션마다 `type`(메인 히어로 / 비포&애프터 / 핵심 포인트 / 사용법&활용 …)과 **`ref_template_image`(템플릿 섹션 미리보기 그림)**가 붙음 → 이미지 모델에 "이 레이아웃 그림처럼 + 이 제품 사진 + 이 기획서·색 규칙으로 그려라"를 섹션별로 요청하는 구조.
- 템플릿 = 섹션 그림 목록(17종 커머스 템플릿, 섹션 15개 안팎, 섹션마다 레이아웃 미리보기 PNG와 표시 이름). 원본은 피그마 파일.
- 편집기: 섹션 목록·순서 변경·삭제, **AI 채팅 수정**(`/campaign-regeneration`: 원본 섹션 그림 + 사용자가 표시한 그림 + 요청문 "제품 원본과 다른 확대샷이야" → 섹션 다시 생성, 약 44초), **텍스트 편집 모드**(`/text-parsing`: 생성 그림 OCR로 글자 상자 → 편집 레이어), **AI 리터치**(부분 지우기·바꾸기), 내보내기 780/860px · JPG/PNG · 한 장/섹션별 · PSD.
- 결과 구성(9섹션): 히어로(장면 위 상단 글자 4줄) → 비포/애프터 → CHECKPOINT(제품 지시선 5) → 카드형 포인트(사진+굵은 2줄 제목+2줄 설명) ×3 → 2규격 비교 → 소재/패드 디테일 2컷 → 4장면 활용(홈카페·탕비실·데스크·바) → 보호가드·주의.

## 같은 상품, 우리 결과(20261009-132404)와의 차이
1. **장면 사진이 하나도 안 만들어졌다** — 앱이 Vertex 프로젝트를 몰라 장면 생성이 건너뛰어짐(no-key). → 수정함(gcloud 로그인 파일의 quota_project_id 자동 사용).
2. 우리 히어로는 중국 사진 위에 큰 영문 세리프 → 제품이 잘리고 글자가 겹침. Moast는 장면 사진 + 상단 여백에 글자.
3. 우리는 글 카드가 많고 사진이 적다(공감/핵심포인트가 글 상자 7개). Moast는 **섹션마다 사진 한 장 + 짧은 글**.
4. Moast는 섹션 목적별로 **새 장면을 생성**(비포/애프터, 4가지 활용 장면, 디테일 클로즈업, 2규격 나란히). 우리는 있는 사진을 배치.
5. 섹션별 다시 만들기(요청문)·텍스트 편집·내보내기 옵션이 Moast에 있고 우리는 템플릿 전체 재렌더만.

## v5 방향 (하이브리드: Moast의 "섹션별 생성" + 우리의 "정확한 HTML 글자")
- 섹션 레시피(섹션 타입별 장면 구도·글자 여백 위치·레이아웃)를 정의하고, **섹션마다 장면 1장을 그 목적에 맞게 생성**(글자 없이, 글자 들어갈 여백을 비워서) → 글자는 HTML로 얹음(오탈자 0, 수정 쉬움).
- 새 템플릿 `card`(Moast 결과 톤: 아이보리 배경, 둥근 흰 카드, 사진 + 굵은 2줄 제목 + 2줄 설명, 히어로는 꽉 찬 장면 + 상단 중앙 글자 4줄, 하단 아이콘 4개 띠).
- 섹션별 "다시 만들기 + 요청문", 글자 바로 고치기, 내보내기(780/860, JPG/PNG, 한 장/섹션별).
