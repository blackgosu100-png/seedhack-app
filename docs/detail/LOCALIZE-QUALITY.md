# 원본 한글화 품질 수정(v11) — 2026-10-12

대표님 판정 "총체적 난국"(안경 세척기 20261012-151942-988732283056)에서 나온 세 문제를 고쳤다.

## 1. 결론

- 한글 줄 겹침: 화면 겹침 0 (전 5곳).
- 히어로 글자 안 보임: 실제 사진 밑 색으로 흰색 전환, 대비 1.2:1 → 15:1.
- 지운 자리 흐린 사각형: 평평한 바탕은 스포이드 색으로 딱 떨어지게, 결 있는 바탕은 옆 결을 복제. AI 는 바뀐 글자 픽셀에만 붙인다.
- 아직 남는 것: 커튼·가죽·사진 위 글은 AI 해상도(768px) 탓에 글자 모양으로 살짝 흐린 자국이 남을 수 있다(아래 4절).

## 2. 지우기(글자 영역마다 둘레 링을 잰다)

| 바탕 | 판정 | 지우는 법 |
|---|---|---|
| 평평한 색 | 둘레 90% 이상이 한 색, 흔들림 ≤ 2.5 | 그 색으로 사각형 채움(페더·흐림 없음) |
| 그라데이션 | 1차(평면)·2차 면이 둘레를 잔차 ≤ 2.2 로 설명 | 그 면 그대로 채움 |
| 고른 결(벽지·천) | 둘레 85% 가 넓은 허용 안 + 네 변 평균 비슷 | 같은 크기 깨끗한 조각 복제 → 안 되면 칸 나눠 복제 → AI |
| 그 밖(사진·커튼·제품 위) | — | AI(장 전체 1회) → 복제 → 결 방향 채움 → 보간 중 고름 |

- AI 붙이기: 모델 출력은 화면비가 달라 1~3% 늘어나고 밀린다 → 밝기 단면으로 배율·이동을 찾아 되돌린다(alignAi). 둘레 띠로 채널별 gain·offset 을 맞추고(colorFit), 원본과 달라진 픽셀(글자·그림자)에만 붙인다(pasteAiPatch, 가장자리 2px).
- 잔상 검사(residueCheck): 경계 단차 · 색 얼룩(평면/세로 결/가로 결 중 가장 잘 맞는 예측과 비교) · 흐림(안쪽 결 ÷ 둘레 결) · 글자 남음(원본 글자색 픽셀이 그대로인 비율). 떨어지면 다른 방법으로 다시.
- AI 는 결 복제로 끝나지 않은 장만 부른다. 글이 남았거나 버려진 장은 그 글만 다시 1회. 대표 사진(gallery)은 hero 로 고른 한 장만 AI.
- 결과는 `localize.json` 레이어마다 `erase{ method, decide, tried, residue }`.

## 3. 글 배치·색(템플릿)

- 넘치는 줄: 옆 빈 바탕으로 상자 넓힘(바탕 격자 색·흔들림이 비슷하고 다른 글·남긴 영문 장식이 없는 곳까지) → 75% 까지 축소 → 2줄 줄바꿈.
- 같은 덩어리 줄은 크기·왼쪽 끝을 맞춘다.
- 겹침 정리(LocCore.nextFix): 위아래로 겹치면 아랫글을 내림, 같은 줄이면 둘 다 줄임, 자리가 없으면 줄임. 남긴 숫자·영문 장식은 못 움직이는 장애물.
- 글자색(LocCore.pickInk): 최종 위치 밑 실제 바탕(24px 격자, render.js 가 계산)에서 큰 글 3:1 · 작은 글 4.5:1 미만이면 흰색/짙은 검정 중 나은 쪽 + 필요하면 옅은 그림자. 둘 다 못 넘으면 원본 색 + 그림자.
- 자체 점검: `page.html` 의 `#page[data-loc-report]`(겹침 전/후·내린 수·색 바꾼 수·hero 대비).

## 추가 수정(v11.1, 2026-10-12 비교 시트 확인 후)

- 영문 장식 지움(d02 "OMNIBEARING"): OCR 이 곡선 영문을 "O4NIBEARIN。" 로 읽고, 끝의 "。" 때문에 영문 표시(latin)가 빠져 지울 글로 들어갔다. → 한자가 한 글자라도 있는 글만 지운다(`isEraseTarget`). 영문·기호 글은 템플릿의 장애물(keep)로 넘긴다.
- 아이콘 지움(d10 빗 아이콘을 "甲"으로 읽음): 한 글자에 확신 0.5 미만이면 아이콘 오인식으로 보고 지우지 않는다(`isIconGuess`).
- 밝은 사각형(d01 제목 자리): 64px 칸 복제가 칸마다 밝기가 달라 옅은 사각형이 생겼고, 잔상 검사는 큰 칸 평균만 봐서 통과시켰다.
  - 지우기: 결 합성(`synthFill`) 추가. 밝기는 둘레로 맞춘 매끈한 면, 잔무늬만 옆 깨끗한 조각에서 가져온다. 옅은 그림자도 마스크에 넣는다(`inkMask soft`).
  - 검사: 12px 칸 밝기 흔들림을 안·바깥으로 비교하는 "조각 얼룩" 추가(결 바탕에서만). 실측 칸 복제 1.5~2.3 → 실패, 결 합성 0.2~0.3 → 통과.
- AI 가 글을 옅게 다시 그려 남기는 경우(d07 모래 본문·d09 "手表"): 지운 그림을 OCR 로 다시 읽어 한자가 보이는 영역은 AI 를 빼고 다시 고르고, 그래도 남으면 보간으로 덮는다.
- 그 밖: Coons 보간 값이 0~255 를 넘어 하늘색 얼룩이 생기던 것(커피 랙 d07) 자름. 단색 채움은 글자가 남았을 때만 다시 시도(밑줄 오탐으로 다시 하다 얼룩이 생기던 것, 커피 랙 d11). 복제·결 합성은 결 바탕에서만(사선 판 위 모자이크 방지). 글줄 방향 채움(`dirFill`) 추가.
- 남은 것: 커피 랙 d07 기울어진 층 라벨 맨 아래 칸 옅은 자국 1곳.
- 획 인페인팅(v11.2, 커피 랙 d07 기울어진 층 라벨): 사각형 채우기는 판 모서리를 가로질러 네모 자국을 남겼다. → 글자 획만(`strokeMask`: 주변 15~19px 평균보다 뚜렷이 어두운/밝은 픽셀 + 글자색, 2px 팽창, 기울어진 글은 네 꼭짓점 안) 바깥→안 순서로 메운다(`inpaintMask`, 이웃 색 중앙값에서 먼 이웃=다른 판은 가중치 낮춤). 기울어진 글은 이 방법을 먼저 해 보고 글자가 남지 않으면 AI 없이 끝. 그 밖의 바탕에서도 후보로 넣어 잔상 검사로 고른다.
- 후보 비교 때 "원본으로 되돌리기"를 "지금 상태로 되돌리기"로 바꿨다(겹친 이웃 글 영역을 지운 것이 원본으로 되살아나던 버그).

## 앱 내 검수(v13, 2026-10-13)

수강생은 결과를 보고 지적·수정을 못 한다. 그래서 앱이 결과를 먼저 보여 준 뒤 **뒤에서** 스스로 검수하고, 걸린 장만 고쳐 다시 그리고, 그래도 남은 장만 "⚠ 확인 필요"로 보여 준다.

### 1. 결론

- 결과가 뜨는 시각은 그대로다. 검수는 결과(done) 뒤에 시작한다(아래 실측).
- 일부러 넣은 결함 3가지(원 밖으로 민 글 · 겹친 두 줄 · 한 줄만 1.6배)는 모두 잡혔고 1회차에 모두 고쳐졌다.
- 상한: 시간 3분 · 비용 $0.40(AI 비전·다시 쓰기·AI 다시 지우기). AI 비전은 그중 80% 까지, 나머지는 다시 쓰기·다시 지우기 몫. 비용 상한을 넘어도 0원짜리 고치기(크기·열 맞춤, 다시 그리기)는 계속한다. 시간 상한이면 멈추고 남은 장은 ⚠.

### 2. 흐름(src/main/detail/loc-qa.js · loc-qa-core.js)

1. 렌더 직후 index.js 가 `job.locQaCtx` 를 두고, 결과 화면을 먼저 띄운 뒤 `afterDone → runLocQaBg` 가 시작한다(카드 결과의 뒤 검수와 같은 자리).
2. 측정: 렌더 결과 `page.html` 을 숨은 창에 그대로 열어(템플릿을 다시 돌리지 않음) 장(이미지 섹션·히어로)마다 잰다.
3. 판정(`judgeSection`) → 고치기(최대 2회) → 걸린 장만 다시 측정. 고친 뒤 없던 종류의 문제가 생긴 장은 plan 을 되돌리고 원래 문제를 ⚠ 로 남긴다.
   - 시간 상한은 단단하다: AI 호출·다시 지우기는 남은 시간 안에 안 끝나면 결과를 버린다(다시 지우기는 임시 파일에 쓰고 제때 끝났을 때만 바꿔 끼움).
4. 다시 그린 렌더는 **같은 탭(out/<렌더 id>)** 을 덮어쓴다. 고친 plan 은 plan.json(한글화만)·plan-localize.json(둘 다)에 저장해 다음에 다시 그려도 유지.
5. 기록: `result.json renders[].locQa = { status, checked, fixed, flagged, ms, costUsd, limitHit, sections:{ id:{ pass, issues[], tries, fixed, why, y } }, steps[] }` · `localize.json qa = { renderId, sections:{ id:{ pass, issues, tries } } }`.
6. 끄기: 설정 `detailLocQa=false` 또는 환경 `SEEDHACK_LOCQA=0`. 상한: `detailLocQaMaxMs` · `detailLocQaMaxUsd` · 모델 `detailLocQaModel`(기본 haiku).

### 6. 남은 한계

### 고친 규칙(원인별)

지우기(localize.js · image-core.js)
- 원·알약·띠 안 글: 도형은 남기고 그 안 글만 지움, 한글은 도형(layer.shape) 안에 맞춤. 테두리 없이 색만 채운 알약도 찾음(글 상자 안 최빈색 — 글자색 픽셀은 뺌 — 의 닫힌 도형, 이미지 끝에 닿은 띠는 제외). 나란한 알약 영역이 겹치면 가운데에서 나눔.
- 원 테두리에 닿은 글의 단색 채움은 원 안만(shapeClip). 단색·면 채움과 결 복제·합성은 "바탕↔글자색 선분 위 픽셀"만 바꿈(inkColorClip) — 글 옆 장식을 직선으로 자르지 않고, 이미 바탕인 그라데이션은 누르지 않음.
- 새 얼룩(원본에 없던 도드라진 점, 밝은·어두운 둘 다)·새 사각형 경계(상자 변 안팎 밝기 차이가 원본보다 +10)를 만드는 후보는 탈락. 획 인페인팅·복제·AI 모두 같은 검사.
- AI: 알약·띠를 지우라고 하지 않음(AI_PROMPT). 붙이기는 글자 획 근처(획 높이 20%)만. 장 전체 변화가 커도 지울 영역 둘레 24px 띠가 맞으면 받음. Vertex 토큰은 동시 요청을 하나로 묶고 네트워크 실패면 2번 더(빨래건조대 8장이 AI 없이 지워졌던 원인).
- 줄 끝 잘린 글자 넓히기는 남기는 영문·숫자(OCR latin)와 글줄 위아래로 이어지는 큰 글자("5个"의 5) 앞에서 멈춤. 테두리 글자는 획 마스크를 더 넓게.
- 글자색: 채움·테두리 두 색이 다 무채색이고 경계 비율 차이가 작으면 픽셀이 많은 쪽이 채움(어두운 판 위 흰 글이 뒤집히던 것).

배치(template.js · inferLayout)
- 정렬은 배치로: 한 줄에 나란한 짧은 글(아이콘 칸 라벨) = 가운데 + label(가장 큰 글이어도 제목 아님), 세로로 쌓인 줄 = 왼쪽·가운데·오른쪽 중 가장 잘 맞는 끝, 같은 높이 3줄 이상 목록 = 역할·크기·굵기 하나로. 예전 "이미지 오른쪽 절반이면 오른쪽 정렬"은 혼자인 줄에만 남음.
- 넓히기: 가운데 글은 가운데를 지킴, 바탕이 바뀌는 칸(테두리선) 앞에서는 글자 크기 1/3 만큼 띄움. 알약·바탕 상자 글은 가운데 + 안쪽 여백, 넘침은 안쪽 폭으로 잼.
