# 🖼 쿠팡 썸네일 자동 생성

상세페이지 작업 폴더의 재료로 대표이미지 1장과 추가이미지 4~6장을 만든다.
코드: `src/main/detail/thumb.js`(만들기·IPC) · `thumb-core.js`(순수 함수, `test/detail/thumb-core.test.js`) · 화면 `src/renderer/thumb.js`.

## 1-2. 강의 원칙 (존버셀러제이 9기 2주차 p.36~43 · 정리: `강의교재_분석/썸네일_강의정리.md`)

- 제품컷보다 연출·착용샷 / 실제 소비자와 닮은 모델 / 주 목적이 보이는 연출 / 소구점(용량·구성품·기능) 직접 표시
- 옵션별 대표이미지는 각 옵션 사진 / 추가이미지 9장은 꼭(대표 B컷 · 상세페이지 1000×1000 자르기)
- IPR: 쿠팡 엠블럼(BEST·쿠팡추천)·로켓배송·무료반품 문구 금지

### 강의와 쿠팡 공식 기준이 다른 곳 → 공식 기준을 따른다
| 항목 | 강의 | 쿠팡 공식(2026-07-07 시행 요약) | 우리 앱 |
|---|---|---|---|
| 대표이미지의 연출·착용샷 | 제품컷보다 연출샷 | 순백 배경 원칙. 연출은 **일부 카테고리 예외**만, 사람 모델 불가 | 대표 = 흰 바탕 누끼. 연출·인물 장면은 **추가이미지 1~2번** |
| 대표이미지 소구점 문구 | "1.2L" 같은 문구 표시 | 텍스트·배지·프로모션 문구 금지 | 문구는 **추가이미지(소구점 컷)에만**. 대표엔 글자 없음 |
| 옵션 색상 | 썸네일·옵션명으로 표현 | 한 장에 여러 색상 옵션 금지 | 대표는 한 옵션. 옵션 모음은 추가이미지, 옵션마다 대표 따로 |

추가이미지(DETAIL)에도 대표 기준이 적용되는지는 확인 못 했다 → 추가이미지 문구도 원문 근거 + IPR·광고 문구 금지로 보수적으로.

## 2. 우리 기준 (규정 → 구현)

| 항목 | 대표이미지 | 추가이미지 |
|---|---|---|
| 크기 | 1000×1000 JPG, 3MB 이하(넘으면 품질을 낮춰 맞춤) | 같음 |
| 배경 | 순백 #FFFFFF — 가장자리 1px 링 99% 이상 250+ 검사 | 장면은 AI 배경 |
| 제품 | 실제 사진의 누끼, 긴 변 85%(75~92% 밖이면 경고), 가장자리 3% 여백 | 실제 누끼·실제 사진만 |
| 글자 | 없음. 원본의 치수 표시·제품 위 글자(상표 포함)는 지운 뒤 누끼 | 치수 숫자(원본 근거)·옵션 이름·기능 라벨 1개만 |
| 로고 | 없음(다른 브랜드 로고 = 빼기) | 같음 |
| 합성 | 바닥 그림자만 | 장면: 배경·소품만 AI, 제품은 실제 누끼 |
| 옵션 | 한 장에 한 옵션 | 옵션 모음은 추가이미지에만 |

AI 가 제품 모양을 그리는 일은 없다. Gemini 에는 **제품 사진을 주지 않고** 빈 배경만 요청한다.

## 3. 흐름

1. **누끼 후보**: 대표(gallery)·옵션(option) 원본 사진 전부 → macOS Vision 누끼(0.4초/6장).
   제품 상자 안의 OCR 글자(치수 표시 `10.5cm`, 라벨·상표 `PIADLIEK`)를 원본에서 지우고 다시 누끼.
   작은 조각(가장 큰 덩어리의 8% 미만) 제거 → 알파 상자로 자르기 → 흰 바탕 미리보기.
   원본 사진 가장자리에 닿은 제품은 "잘림 의심"으로 대표 후보에서 뺀다.
2. **고르기(Claude CLI·Read 1회)**: 후보마다 제품 전체·1대·손/사람·다른 물건·덧그린 글자·같은 제품·각도·점수 →
   `pickHero` 점수로 대표 1장. 같은 호출에서 옵션 구분 라벨, 치수(원문 인용), 기능·구성품 사진, 장면 주제.
3. **만들기(오프스크린 창 1000×1000 캡처)**:
   - 대표: 흰 바탕 + 누끼 + 타원 바닥 그림자
   - 장면: AI 배경(제품 없이, 면이 아래 40%, 가운데 비움) + 누끼(60%, 면 위) + 접지 그림자
   - 사이즈: 누끼 + 가로·높이 치수선(+깊이 한 줄). 숫자는 상품 정보 글·사진 OCR 에 **있는 숫자만**(`dimsGrounded`)
   - 옵션 모음: 겉모양이 다른 옵션 2~6개, 회색 칸 + 이름
   - 핵심 기능: 글자·로고 없는 상세 사진 꽉 채움 + 라벨 1개
   - 구성품: 구성품 사진(있을 때만)
4. **검수**: 픽셀(순백·잘림·채움·용량) + 비전(Claude CLI·Read 1회: 실제 사진과 같은 모양 · 잘림 · 다른 브랜드 로고 · 글자 · 합성 어색함)
   → 장마다 통과 / 확인 필요 / 빼기. 내보내기는 "빼기"를 뺀 장만.

결과: `<작업>/thumb/NN-<kind>.jpg`, `thumb.json`(후보 판정·치수 근거·비용·시간), 내보내기 `thumb/export/01_대표이미지.jpg …`.

- 이미지 생성 실제 청구: 상품당 배경 2장 ≈ 110원
- 시간 대부분은 Claude 판정(92~236초)·검수(131~268초)
- 슬라이서 옵션별 대표의 "확인"은 제품 앞 빨간 라벨의 중국어, "빼기"는 원본 사진이 잘린 SKU

직접 보고 판정
- 대표 3개: 실제 사진 누끼 · 순백 · 잘림 없음. 제품 위 덧그린 글자(`10.5cm 7cm`, `大葱切沫机`)는 지워짐
- 인물 장면: 식당 주방·정육점·집 주방에 타겟과 닮은 인물이 뒤에서 일하는 모습, 제품은 실제 누끼 그대로
- 소구점 라벨은 원문에 있는 말만(예: 두께 2.5~15mm, 폭 37~57.5cm 조절)
- 사이즈 숫자는 원본 그대로(슬라이서 38×27.5×27.5 · 커피 랙 37~57.5 / 13.5·20.5 / 33.7)

고치는 중에 잡힌 문제
- 대표 갤러리에 끼워 넣은 다른 상품(타이머·만두기계)이 B컷으로 뽑혔고, 비전 검수도 한 번 "같은 제품"이라 통과시켰다 → B컷은 옵션(SKU) 사진 + 색 분포 일치로만
- 상세 일부: 한글화한 상세페이지에도 원본의 모델·중국어(品牌形象代言人)가 남은 섹션이 있다 → 검수가 걸러 냄(빼기·확인)
- 배경 생성 1회 시간 초과(120초) → 다음 지역으로 다시 보내게 고침

알려진 한계
- 실행마다 옵션 칸 수·기능 사진·상세 일부 섹션이 달라진다
- 인물 장면 배경에 가끔 둥근 접시 자국 같은 어색한 무늬(대파 1장)
- 상세 일부는 섹션 위 780px 만 잘라 아래 사진이 반쯤 잘린다
- OCR 이 못 읽은 작은 라벨 글자는 남는다 → "확인 필요"로 표시

## 4-2. 강의 반영(v2, 2026-10-13)

추가이미지 순서(최대 9장): 인물 장면 → 사용 장면 → 소구점 → 사이즈 → 옵션 모음 → 기능 → 구성품 → 대표 B컷 → 상세 일부(모자란 만큼)
- **인물 장면**: brief 의 타겟과 닮은 평범한 인물이 뒤에서 일하는 배경(흐림)을 AI 로, 제품은 실제 누끼를 앞에. 인물이 제품을 만지는 장면은 만들지 않는다(손이 제품 모양을 바꾸게 되므로)
- **사용 장면**: 타겟의 주 목적 상황(situation)을 배경 프롬프트에
- **소구점**: 라벨 2~3개, 12자 이내, 라벨 속 숫자는 원문에 있어야(`appealOk`), IPR·광고 문구 금지
- **대표 B컷**: **옵션(SKU) 사진**에서만, 대표와 색 분포 일치 0.55 이상(`pickBcut`). 대표 갤러리에는 판매자가 끼워 넣은 다른 상품(슬라이서 → 주방 타이머, 대파 분쇄기 → 흰 만두기계)이 섞여 있고, Claude 판정·검수 둘 다 이를 "같은 제품"으로 놓친 적이 있다(2026-10-13 실측). 검수에서 빠진 B컷·상세 일부는 자동으로 버린다
- **상세 일부**: 지금 선택된 상세페이지 렌더에서 머리·스펙·주의·FAQ 를 뺀 섹션을 고르게 골라 1000×1000(780보다 길면 위 780)
- **옵션별 대표이미지**: 옵션 사진마다 흰 바탕 규정형 1장(`thumb/options/`), 이름은 옵션명 한국어. 픽셀 검수만
- **IPR 검수**: 우리가 넣는 글(`hasIprText`) + 비전 검수 `coupang_mark`(엠블럼·로켓배송·무료반품) → 있으면 빼기

## 4-3. 앱 화면·자동 만들기 (2026-10-22, 대표님 결정)

- 상세페이지 결과 맨 위 탭 `📄 상세페이지 | 🖼 썸네일`. 썸네일 탭에선 상세페이지 전용 버튼(피그마·HTML·템플릿·내보내기)과 렌더 탭을 숨긴다
- 탭 배지: `곧 시작` → `만드는 중 43%` → `10장`
- 맨 위: 결론 한 줄 + 숫자 3개(장수 · 통과/확인 · 이미지 생성 원) + `⬇ JPG로 저장`(글자 버튼) · ↻ 다시 만들기 · 📂 폴더(아이콘 + 오버 설명)
- 쿠팡 등록 순서 줄: `대표` 칸(크게) | `추가 1~9` 칸, 빈 칸은 "비어 있음", 빠진 장은 줄 끝에 흐리게
- 칸을 누르면 아래에 크게 + `⭐ 대표로`(흰 바탕 장만: 대표·다른 각도) · `🙈 빼기/↩ 다시 넣기` · `◀ ▶` → `thumb.json` 에 바로 저장(`applyEdit`), 내보내기는 화면 순서 그대로(`exportPick`)
- 옵션별 대표이미지는 아래 접기
- **자동**: 상세페이지가 끝나면(뒤 작업 `bg` 제외) `afterDone` → `thumbHook.auto(jobId, { busy })`. 뒤 검수(qaReview)·원본 한글화 검수·다른 상세 작업이 도는 동안은 5초마다 기다렸다가 시작(최대 15분). 이미 `thumb/thumb.json` 이 있으면 안 함, 다시 만들기는 탭의 ↻
- 스위치: 썸네일 탭 아래 "상세페이지가 끝나면 자동으로 만들기"(설정 `thumbAuto`, 기본 켬)

- 입력: 상품 키워드(작업의 `source.keyword` 또는 리스트업 행). 앱의 쿠팡 탭 백그라운드 뷰(main.js `coupangBgView("search")`)로 검색 1페이지를 읽는다 — 이미 쓰는 검색 화면 읽기 재사용, 추가 요청 없음.
- 읽을 것: 상위 36개 상품의 썸네일 주소·상품명·가격·리뷰 수·광고 여부·로켓 여부.
- 화면: 실제 쿠팡 검색 결과와 같은 4열 격자(카드 크기·글자 크기 같게)에 **우리 후보 1장을 n번째 칸에 끼워** 보여 준다.
  n = 1·5·9 중 선택. 후보(대표 / 장면 / 사이즈)를 바꿔 끼우며 비교. 광고 칸은 회색 테두리.
- 판정은 내지 않고 참고 지표만: "흰 바탕 비율 31/36", "제품 크기 중앙값 78%", "우리 후보 82%".

- 강의의 "주변 지인에게 평가받기"를 대신한다: 한 화면에 후보 3~4개를 같은 칸에 번갈아 끼워 "내가 손님이면 어느 것을 누를까"를 바로 본다. 대표님·수강생이 고른 후보를 기록(`thumb.json` picks)해 다음 추천에 반영.

### 5-2. 상위 상품 썸네일 벤치마킹·차별화 제안
- 상위 10개 썸네일을 받아 픽셀 지표(배경 흰색 여부·제품 채움·주색) + 비전 1회(각도·구도·소품·글자 유무)로 표를 만든다.
- 차별화 제안 규칙(근거 숫자와 함께):
  - 상위 다수가 정면이면 → 사선(3/4) 컷 후보를 먼저
  - 제품 채움 중앙값보다 작으면 → 채움 85%로
  - 다들 흰 바탕 + 같은 색 제품이면 → 추가이미지 1번을 장면 컷으로(대표는 규정상 흰 바탕 유지)
  - 상위에 사이즈 컷이 없으면 → 사이즈를 추가 2번으로
- 대표이미지 규정(흰 바탕·글자 없음)은 벤치마킹 결과와 상관없이 지킨다. 경쟁사가 글자를 넣었어도 따라 하지 않는다.
- 비용 예상: 비전 1회(Claude CLI) — 이미지 생성 없음.

### 5-3. 판매 부진 시 썸네일 교체 후보 재생성
- 근거(강의 4주차): 첫 한 달은 클릭률·전환율이 생명, "노출되는데 안 팔리면 즉시 판매가 조정·썸네일 교체", 2~3주 부진하면 타겟 키워드를 바꿔 새로 등록.
- 입력: 마진 대시보드·Wing 판매 데이터(상품별 노출·클릭·판매). 등록일 기준 7·14·21일에 점검.
- 신호(판정 아님, 참고 지표): 노출은 있는데 클릭률이 같은 키워드 상위 평균보다 낮음 → 썸네일 문제 / 클릭은 되는데 판매 없음 → 가격·상세 문제.
- 동작: 썸네일 문제 신호면 "교체 후보 만들기" 버튼 → 지금 대표와 **다른 각도(B컷)**·**다른 연출 장면**·**소구점 컷을 1번으로** 올린 세트 2~3안을 다시 생성하고, 5-1 그리드 미리보기로 지금 썸네일과 나란히 비교.
- 교체 이력(날짜·바꾼 장·그 뒤 7일 클릭률)을 `thumb/history.json` 에 남겨 무엇이 효과 있었는지 쌓는다.
