## 구현 메모
- **배경 판정**: 상자(+4px) 둘레 4px 띠에서 `roughness`(이웃 픽셀 간 평균 차이)와 `variance`(띠 전체 표준편차)를 잰다. `roughness ≤ 6 && variance ≤ 48` → erase, 아니면 keep. 단색 0/0, 그라데이션 ≈0.1~1, 노이즈 사진 30+ 라서 여유 있게 갈린다(`ERASE_RULE` 로 조절 가능).
- **메우기**: 행별 좌↔우 보간과 열별 상↔하 보간을 상자 가로세로 비율로 섞는다(글 한 줄처럼 넓은 상자는 세로 보간 비중↑ → 세로 그라데이션에서 띠 자국 없음). 이미지 가장자리에 붙어 둘레가 한쪽만 있으면 그쪽 색.
- **상자 병합**: 6px 안에 붙은 상자는 하나로 합쳐 한 번에 메운다(이음새·둘레에 이웃 글자 섞임 방지). 결과 `boxesOut` 은 원래 상자마다 돌려준다(병합 그룹의 판정을 공유).
- Vision 은 6장씩 묶어 프로세스 1회 실행(진행 표시는 장마다 `onProgress`).

## 알려진 한계
- **윈도우 OCR 품질**: tesseract chi_sim 은 샘플에서도 글자 오인식(可折叠→可折墅)이 있고 실제 상세 이미지(작은 글자·장식 글꼴·배경 무늬)에서는 재현율이 더 떨어질 수 있다. 상자 좌표는 쓸 만하므로 지우기는 되지만 번역 원문 품질이 낮다. 첫 실행 때 언어 데이터(약 7.7MB)를 jsdelivr 에서 내려받아야 한다(오프라인이면 `none`).
- tesseract.js 워커가 시작할 때 stderr 에 `Error opening data file ./ȇ…raineddata` 가 한 줄 찍힌다 — tesseract 코어의 알려진 무해한 메시지(인식 결과는 정상). 앱 로그에는 가지 않는다.
- 지우기는 "단색·완만한 그라데이션" 배경 전제. 글자가 도형 경계·선 위에 걸치면 그 부분은 보간으로 뭉개진다(keep 으로 가지 않을 수 있음). 반투명 워터마크·로고는 OCR 로 안 잡히면 그대로 남는다.
- 샘플은 HTML 로 그린 합성 이미지(실제 1688 이미지 아님). 실사진 위 글자 판정(`keep`)은 노이즈·도형으로 흉내낸 사진 기준이며, 매우 매끈한 실사진(흰 스튜디오 배경)은 erase 로 판정될 수 있다 — 그 경우에도 결과는 자연스럽다.
- Vision 은 `conf` 를 0.3/0.5/1.0 같은 거친 값으로 준다(Vision 특성). `finishBoxes` 는 conf < 0.15 만 버린다.
- 배포판(electron-builder) 주의: `build.files` 에 `tools/**` 가 없어 **맥 패키지에서는 ocr.swift 가 번들되지 않는다**(→ "OCR 소스가 없습니다" 안내 후 tesseract). 윈도우 배포판은 tesseract.js 의 wasm/worker 가 asar 안에 있으면 못 돌 수 있어 `asarUnpack: ["node_modules/tesseract.js/**", "node_modules/tesseract.js-core/**"]` 와 `files` 에 `tools/ocr-mac/**` 추가가 필요하다 — package.json build 설정은 내 소유가 아니라 손대지 않았다(지휘자 결정 요청).

## 규약과 다르게 한 점
- `ocrFile(file, { provider, log })`, `ocrImages(images, { onProgress, log, provider })` — 규약에 없는 선택 인자 `provider`(하네스에서 제공자 강제)·`log`(기존 `log(level, text)` 꼴) 추가. 기본값은 규약대로.
- `ocrFile` 반환에 `provider` 를 덧붙였다(`{ w, h, boxes, provider }`).
- `cleanImage` 에 선택 인자 `pad`(기본 4)·`ring`(기본 4) 추가. 반환은 규약 그대로.
- image-core 는 규약의 함수 외에 `cleanBitmap`, `meanDiff`, `toHex`, `hasCJK`, `makeBitmap`, `fillRect` 를 더 내보낸다(image.js·테스트가 쓴다).
- `estimateBackground` 결과에 `roughness`·`samples` 를 추가(규약의 `color/variance/gradient` 는 그대로). 결정 규칙은 `variance` 만이 아니라 `roughness` 를 주로 본다(그라데이션은 variance 가 커도 매끈하므로).
- `tesseract.js` 언어는 규약 `chi_sim` 에 `eng` 를 더해 `chi_sim+eng`(숫자·영문 치수 인식 보강).
- 환경변수 `SEEDHACK_OCR_NO_SWIFTC=1` 이면 swiftc 를 없는 것으로 본다(B-7 하네스용).
- `test/detail/img/make-samples.js` 는 `data:` URL 로 두 번째 창부터 `ERR_FAILED` 가 나서 임시 HTML 파일(`userData/sample-<id>.html`)을 창 하나에 차례로 `loadFile` 한다.

## 재설계: 사진 영역 잘라내기 (실제 1688 상품 32장 기준)

실제 작업 폴더(`~/Library/Application Support/씨드핵/detail/20261009-080956-948424797701`, raw 32장 + ocr.json)를 보니 중국 상세 이미지는 한쪽에 큰 글자·밑줄·점·배지, 나머지에 제품 사진이라 글자를 "지우면" 빈 벽·얼룩이 남고 OCR 에 안 잡히는 장식이 남는다. → **글자 없는 사진 영역만 잘라내는** `cropPhoto` 로 바꿨다(기존 `cleanImage`·`autoTrim`·`cropTextBand` 는 단색 배경용 fallback 으로 그대로 둠).

### API (확정)
- `image-core.js: findPhotoRegion({ w, h, boxes, bitmap, grid=16, pad=6, minArea=0.3, minW=0.55, minContent=0.12 }) → { rect, contentRatio, coverage } | null`
  글자 상자(+pad)를 16px 격자에 칠하고 빈 칸만의 극대 직사각형(히스토그램 방식)을 모두 뽑아 `점수 = 면적 × (0.3 + contentRatio)` 최대를 고른다. 조건: 면적 ≥30%, 가로 ≥55%(세로가 가로의 1.3배 넘는 긴 이미지는 세로 ≥55%·가로 ≥35% 도 허용), contentRatio ≥0.12. 상자 0개면 전체.
- `image-core.js: settleBoxesInRect(rect, boxes) → { rect, residual }` — 가장자리에 얇게 걸친 상자는 rect 를 줄이고, 안쪽 상자는 `residual`(cropPhoto 가 eraseRect 로 지움).
- `image-core.js: trimEdgeBands(bitmap, { tol=14, uniformFrac=0.85, minRun=0.3, sameBand=24, minDelta=28, skip=6, maxFrac=0.2, limitBase }) → { x,y,w,h, cut:{top,bottom,left,right} }`
  가장자리에서 안쪽으로 줄마다 평균색·균일도를 보며 (거의 단색 또는 폭 30% 이상 같은 색 구간 = 배지 조각) 띠를 이어 가고(밑줄·점은 skip 6줄까지 건너뜀), 띠 다음 영역과 ΔE ≥ 28 일 때만 잘라낸다. 한계(원본의 20%)까지 이어지면 배경이므로 안 자른다. 둥근 배지 조각은 +16px, 단색 띠는 +4px 더.
- `image-core.js: textureRatio(bitmap) → 0~1` (2px 이웃과 12 이상 다른 픽셀 비율 — 사진 ≥0.1, 단색 판·그라데이션 <0.05)
- `image.js: cropPhoto(file, boxes, out, opts) → { out, w, h, rect(원본 좌표), coverage(크롭 면적/원본), contentRatio, texture, residual, cutTop, cutBottom, ok }`

### API (확정)
`src/main/detail/localize.js: localizeImage({ file, ocrBoxes, out, ai=true, settings, env, log, fetchImpl, maxDiff=14 }) → { out, w, h, promo, layers:[{ x,y,w,h(지운/글자 놓을 영역), textBox, zh, role, style:{ color, bgColor, pill, borderColor, fontWeight, fontSizePx, align, rotate? }, erased:"js"|"ai"|"kept", how }], ai:{ used, accepted, diff, ms, region, error? } }`
- ① 덩어리: `groupTextBlocks`(같은 줄·가로 간격 ≤ 1.2×높이, 숫자 상자는 따로). 숫자·단위만(13.5cm·37-57.5cm·4.17kg/5.15kg)은 **지우지 않음**(role number, erased kept). 역할 `assignRoles`: number · promo · note(*·以上…·작은 글) · title(가장 큰 글) · sub(알약 배너·긴 글) · label(6자 이하).
- ② 스타일 `textStyle`: 상자 테두리 줄 = 바탕, 바탕에서 먼 픽셀 = 획 → 글자색(먼 쪽 절반 평균)·획 두께/높이로 굵기(400/500/700/800)·크기(글자 두께 × 0.92)·정렬(가운데/좌/우). 알약 `detectPill`: 글자 위·아래로 "가로로 같은 색인 줄"(테두리선) + 좌우 테두리 → 배너 전체 사각형·테두리색·채움색(끝없이 이어지는 띠는 제외). 기울어진 글: Vision 이 이제 `quad`(네 꼭짓점)·`angle` 을 주므로(ocr.swift·ocr.js 수정) 글자 두께로 크기를 재고 `style.rotate`.
- ③ 지우기 `eraseMode`(실측 근거): 둘레가 완전히 매끈(거칠기 ≤ 0.2·분산 ≤ 3 — 인쇄 단색·그라데이션) → 보간; 둘레의 85% 이상이 한 색이고 그 색이 흔들리지 않음(바탕 결 sd ≤ 2.5) 또는 "한 색 바탕 + 선" 두 색 → 그 색 단색(`safeEraseRect` 가 밑줄·표 테두리 앞에서 멈춰 **선은 살림**); 그 밖(사진 벽·사선 판 경계) → **AI 편집 1회**(Vertex 다지역 경로 재사용, 프롬프트 "Remove only the Chinese text and its decorative banner/pill; keep every other pixel identical; do not change the product" + 지울 글·위치 목록). AI 결과를 원본 크기로 맞춰 **글자 영역 밖** 평균 차이(1/8 축소) ≤ 14 면 채택 — 그래도 **글자 영역만** 원본 위에 붙인다(바깥 띠에서 색 차이를 재서 맞춤, 가장자리 6px 섞기, 기울어진 글은 글자 네 꼭짓점 다각형으로만). 14 넘으면 버리고 JS(다수 색)로 대체.
- ④ 홍보 판별: 글 중 promo(공장·有限公司·认证·专利·定制·一件代发·七天…) ≥ 2개 또는 40% 이상, 또는 회사 소개 고유어(有限公司·合作伙伴·专利证书·厂房·定制流程…) → `promo:true`, **홍보 이미지는 AI 를 쓰지 않음**(상세페이지에서 빼는 게 기본).
- 순수 도우미는 image-core.js(`isNumberText, isPromoText, groupTextBlocks, assignRoles, textStyle, detectPill, ringMode, safeEraseRect, eraseMode, nearestAspect, diffOutside, pasteMasks, growQuad`), localize.js 는 입출력·AI 호출.
