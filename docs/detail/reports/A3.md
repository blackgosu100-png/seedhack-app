## 5. 알려진 한계

- **배포판 서버 중계는 아직 동작하지 않는다.** `copy.js: viaServer()` 가 `DASHBOARD_URL/api/signal/ai` 에 `{ vendor_id, task:"detail", input }` 를 보내지만 서버(web/…/api/signal/ai/route.js)에 `detail` 처리기가 없다 → 실패 → `how:"rules"`, `tried:"server"`, `error` 기록. 서버는 `COPY_SYSTEM`·`COPY_SCHEMA`·`renderCopyInput` 을 그대로 옮겨 `result` 에 Copy JSON 을 돌려주면 된다.
- 규칙 기반 카피는 템플릿 문장이라 상품군(수납/주방/욕실/기본 4종 pain 세트, 특징 사전 17개)을 벗어나면 평범하다. 특징 사전에 없는 상품은 FALLBACK 3개(꼼꼼한 마감·간편한 사용·실용적인 디자인)로 채운다.
- 규칙 usp 의 imageId 는 이미지 단위라서 긴 이미지의 두 번째 조각에 있는 특징(샘플 d05 防水)도 첫 조각(`d05_01`)에 연결된다.
- 숫자 검증은 "단위가 붙은 수치"만 본다(cm·mm·kg·g·L·개·장·년·일·%·W·V 등 40여 단위). 단위 없는 숫자("3단계")는 그대로 둔다. 한자 숫자(三)는 보지 않는다.
- 금지어 "최고" 는 "최고급" 도 잡는다(의도). "항균·살균" 은 원문(抗菌)에 있을 수 있어 금지어에 넣지 않았다 — 필요하면 `BANNED` 에 추가.
- (해결) OCR 의 "7天无理由退换" 같은 중국 판매자 약속 → 7절 정책 약속 필터로 막음. 단, 필터는 한국어 낱말 기준이라 "교환형 필터" 같은 제품 설명의 "교환" 도 약속으로 보고 바꾼다(오검출 가능, 안전 쪽으로).

## 6. 규약과 다르게 한 점 (제안)

1. `writeCopy` 반환에 `tried`(시도한 AI 경로)·`model`·`usage`·`elapsedMs`·`fixes`(정화 내역)·`raw`(AI 원본) 를 **추가**했다. 규약의 `{ copy, how, costUsd?, error? }` 는 그대로다. AI 가 실패해 규칙으로 내려가면 `how:"rules"` 이고 어떤 경로를 시도했는지는 `tried` 에 있다.
2. `sanitizeCopy(copy, input)` 은 `{ copy, fixes }` 를 돌려준다(규약은 반환값 미정).
3. `buildPlan` 에 선택 인자 `translations`(zh→ko)·`copyInput`·`jobId`·`now` 를 **추가**했다. 사진 위 kept 상자를 덮는 overlay 한글 문구는 Copy 에 없어서 번역표가 필요하다(없으면 그 이미지의 캡션 제목으로 덮어 중국어가 그대로 보이지 않게 한다). A5 는 `buildPlan({ ..., translations: koMap, copyInput, jobId })` 로 부르면 된다.
4. plan 의 이미지 경로 구분자는 윈도우에서도 `/` 다(템플릿이 `file://` URL 로 읽으므로). `relPath()` 가 절대경로·역슬래시를 `clean/x.png` 로 정리한다.
5. hero 대체 선택(갤러리 없을 때)은 "가장 정사각형에 가까운 상세 이미지" 중에서 **사이즈 표·구성·주의·스펙으로 분류된 이미지는 뺀다**(샘플에서 구성표 d08 이 가장 정사각형이라 hero 가 되는 것을 막음).

## 7. 정책 약속 필터 (추가 작업 1)

중국 판매자 원문(OCR·상세글)의 배송·반품·보증 약속은 **입력 근거가 있어도 통과시키지 않는다**(근거 규칙의 예외).
- `copy.js`: `POLICY` 3종 — warranty(품질 보증·정품·정식 수입), return(교환·반품·환불·무상·보증·보장·A/S), shipping(무료배송·당일/익일 배송·N일/시간 배송·발송·도착). `policyKind(sentence)`, `scrubPolicy(text, {short})`, 중립 문장 `NEUTRAL`(교환·반품은 쿠팡 정책을 따릅니다 / 배송 일정은 주문 화면 안내를 확인해 주세요 / 품질 관련 문의는 판매자에게 남겨 주세요) + `NEUTRAL_FAQ`(중립 Q/A 3쌍).
- `rulesCopy`: OCR 줄(captions·size_note·package_items·notice)·속성표(spec)에서 약속 줄을 **원천 제거**, faq 배송·교환 항목은 중립 Q/A, notice 기본 문장에 중립 문장 포함.
- `lintCopy`: 약속 문장을 `kind:"policy"` issue 로 보고(금지어는 `kind:"banned"`). 중립 문장 안의 "쿠팡" 은 금지어 예외(중립 문장 집합 `NEUTRAL_SET` 만).
- `sanitizeCopy`: 긴 칸(desc·notice·faq a·size_note 등)은 약속 문장을 종류별 중립 문장으로 교체(칸 안 중복 없음), 짧은 칸(name_ko·headline·sub·badges·usp/caption title·cta)은 제거 후 규칙 문장, faq 는 q 가 약속이면 쌍 전체를 중립 Q/A 로, spec 은 그 줄 제거, notice 는 6개 상한에 중립 문장이 밀리지 않게.
- `writeCopy` 의 "금지어 과다 → rules" 판정은 banned 만 센다(정책 약속은 교체 가능).
- `COPY_SYSTEM` 10번 원칙 추가(중국 판매자의 약속은 옮기지 말고 중립 문장으로).
- 테스트: `copy.test.js` "정책 약속 필터 …" — 샘플 OCR 의 "7일 무조건 교환·반품" 이 규칙 카피에 없고 중립 문장이 있음, AI 카피 흉내(notice·faq·usp·captions·badges·headline·spec 에 약속 심기) → 정화 후 약속 0·중립 문장 존재·lint 통과·스키마 통과.

## 24. v5 지휘자 판정 반영 — 체크포인트 좌표 · 규격 2종 · card 추천 · 성능 단정 완화
