## 알려진 한계
- 피그마 플러그인은 피그마에서 실제 실행해 보지 않았다(API 문서 기준, 문법 검사만).
- 오프스크린 창은 `destroy()` 로 바로 지우면 다음 창의 렌더러가 죽는다(ERR_FAILED, Electron 44) → `close()` 후 `closed` 대기(`closeWindow`). A5 가 창을 따로 만들면 같은 규칙을 따라야 한다.
- 섹션 하나가 3000px 를 넘으면(A3 plan 의 spec 3932px: 긴 이미지 + 표) 그 섹션만 3000 단위로 잘라 슬라이스 경계가 섹션 안에 생긴다(규약 허용). A3 가 긴 이미지를 `cuts` 로 나누면 줄어든다.
- A3 파이프라인 plan(feature 12개)은 전체 20,326px 로 D-2 범위(≤20,000) 를 조금 넘는다 — 섹션 수·이미지 수는 A3 몫. 하네스는 파이프라인 plan 에는 높이 범위 검사를 걸지 않는다.
- 사진 위 overlay 띠는 반투명이라 명도 대비를 정확히 잴 수 없어 띠 색 자체로 계산한다(`check()`).
- hero 사진 상자는 520px 높이·가운데 맞춤이라 정사각 사진은 양옆에 여백이 남는다(사진 자체 배경색이 보임).

## 규약과 다르게 한 점
- **샘플 plan 파일 이름**: 지시된 `test/detail/fixture/plan-sample.json` 은 A3 의 `test/detail/copy-harness.js` 가 파이프라인 결과로 **덮어쓴다**(실행할 때마다). 충돌을 피하려고 A4 손 샘플은 `plan-sample.a4.json` 으로 두고, 하네스는 `plan-sample.json` 이 있으면 그것도 `pipeline-clean` 으로 함께 렌더한다.
- `renderPlan` 반환값에 규약 외 항목 추가: `figmaBundle`, `totalHeight`, `sections`, `check`, `consoleErrors`, 슬라이스에 `bytes`·`quality`. manifest 에 `product`·`slices`·섹션 `n` 추가.
- `figma-manifest.json` 의 feature 레이어는 `#feature.<섹션번호>.image` 처럼 섹션 번호를 넣는다(feature 가 여러 개라서).
- 공통 CSS `common/base.css` 를 추가(규약의 template 3종 파일 외). 템플릿 index.html 이 `../../fonts.css` 로 앱 Pretendard 를 재사용.
- ESM 진입 스크립트(하네스·샘플 생성기)는 top-level `await app.whenReady()` 가 영영 안 끝나서(모듈 로딩이 끝나야 ready) `app.whenReady().then(...)` 로 썼다 — A5 e2e 도 같은 함정 주의.
